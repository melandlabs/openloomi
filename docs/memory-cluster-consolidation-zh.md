# 记忆簇与竞争机制设计思路

## 背景

当前记忆遗忘机制以单条记忆为单位进行价值评分，并结合时间、访问次数、重要性、媒体引用和 pin 状态，决定记忆是否进入后续分层压缩流程。这个设计适合控制记忆规模，也能让短期记忆逐步沉淀为中长期摘要。

如果未来希望进一步提升长期记忆质量，可以在现有 forgetting engine 之外，引入一个轻量的“记忆簇”层。它不负责替换现有分层、压缩和归档逻辑，而是补充一个基于重复证据和再激活的长期记忆整合视角。

## 核心想法

不要在写入入口强行判断一条信息是否是噪声，而是先让信息留下较弱的记忆痕迹。后续如果相似信息反复出现，或者被多次检索和使用，就合并成记忆簇并逐渐增强；如果只是一次性信息，则因为缺少再激活和重复证据而自然衰减。

也就是说，记忆质量不只来自单条记录的即时评分，还来自一段时间内多条相似痕迹之间的相互支持。

## 概念划分

- Trace：一次原始记忆痕迹，例如一条消息、一次观察或一次交互片段。
- Cluster：多条相似 Trace 形成的记忆模式，用来表达“这个主题或偏好反复出现过”。
- Summary：稳定 Cluster 的长期可读表达，可以作为后续检索和上下文注入的材料。

简化后的关系是：

```text
Trace 是证据
Cluster 是记忆模式
Summary 是稳定记忆的可读表达
```

## 与现有机制的关系

这个方向不是替换当前 forgetting engine，而是作为未来增强层：

- 现有机制继续负责记忆分层、压缩、归档和硬删除策略。
- 记忆簇机制负责从多条痕迹中识别稳定模式。
- 低价值的孤立 Trace 可以继续被现有遗忘策略压缩或归档。
- 稳定 Cluster 可以作为摘要生成、长期记忆保留和冲突处理的额外信号。

这样可以先保持当前线上行为不变，再通过实验或 benchmark 评估是否值得引入实现。

## 可能收益

- 减少对单条 importance 判断的依赖。
- 降低一次性噪声进入长期记忆的影响。
- 让稳定偏好从重复证据中自然形成。
- 让相互冲突的记忆可以通过证据数量、最近激活和稳定性进行竞争。
- 为后续 memory benchmark 提供更清晰的机制级对比目标。

## 简化流程

```text
1. 新信息先写入为弱 Trace。
2. 如果和已有 Cluster 足够相似，就并入该 Cluster。
3. Cluster 根据重复证据、访问次数和最近激活逐步增强。
4. 证据足够稳定后，Cluster 生成或刷新 Summary。
5. 长期未激活、证据不足的 Cluster 逐渐衰减，并交给现有遗忘流程处理。
```

## 竞争与冲突

当新 Trace 与已有 Cluster 表达相似主题但结论相反时，不一定要立刻覆盖旧记忆。可以先形成竞争关系：

- 旧 Cluster 保留原有证据和稳定性。
- 新 Trace 或新 Cluster 记录新的相反证据。
- 如果新方向持续出现，它的稳定性逐步上升。
- 查询时优先使用最近持续激活、证据更多、置信度更高的 Cluster。

这可以避免一次临时指令立刻覆盖长期偏好，同时也允许真实偏好变化在多次证据后逐步生效。

## 非目标

本文档不要求立即修改现有遗忘逻辑，也不引入新的线上行为。它只是为后续 memory consolidation、冲突记忆处理和 benchmark 设计提供一个小范围讨论草稿。

本文档也不主张在写入入口增加更复杂的噪声分类器。相反，它倾向于把“是否值得长期保留”从一次性判断，改成由重复证据、再激活和竞争机制共同决定。

## 后续验证方向

如果未来实现这个方向，可以先用离线 benchmark 验证，而不是直接接入线上路径。几个可观察指标包括：

- 噪声召回率：一次性噪声是否减少出现在长期检索结果中。
- 稳定偏好召回准确率：多次出现的用户偏好是否更容易被保留。
- 临时指令污染率：一次临时上下文是否会错误变成长期偏好。
- 偏好变化适应速度：用户真实偏好改变后，新记忆多久能稳定胜出。
- 冲突解释能力：系统是否能说明当前结论由哪些证据支持。

## 最小实验路径

一个较小的实现路径可以是：

1. 先只在 benchmark 中构造 Trace 和 Cluster，不改变线上存储结构。
2. 对比当前单条记忆评分策略和 Cluster 聚合策略的检索结果。
3. 只在离线评估显示收益后，再考虑把 Cluster 信号接入 summary 或 retention policy。

这样可以把设计讨论、评估验证和线上行为变更拆开，降低后续实现风险。
